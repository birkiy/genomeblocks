# About the documentation site

This `docs/` folder is a Jekyll site built with the [`just-the-docs`](https://just-the-docs.com) remote theme and deployed to GitHub Pages via the `.github/workflows/pages.yml` Actions workflow.

## Building locally

```bash
cd docs
bundle install
bundle exec jekyll serve --livereload
# open http://127.0.0.1:4000
```

## Enabling Pages on the repository

1. In the repo settings → **Pages**, set the source to **GitHub Actions**.
2. Push to `main`; the `Deploy GitHub Pages` workflow runs automatically on every change under `docs/`.
3. The site goes live at `https://<user>.github.io/<repo>/`.

## Diagrams and the Benchmarks page are generated

- **Design diagrams.** `python docs/_tools/build_diagrams.py` writes one SVG per
  figure to `_includes/diagrams/`. Each figure is drawn on explicit coordinates
  in that script. Shapes carry classes (`bx green`, `ln navy`, …) that
  `_sass/custom/custom.scss` maps onto the site's colour tokens, so the figures
  follow the theme. Pages include them inside
  `<figure class="gb-fig">…<figcaption>`.
- **Benchmarks.** `python benchmarks/build_site.py` reads
  `benchmarks/results/*.json` and writes `benchmarks/index.md` with inline SVG
  charts, so rerunning the suite and the builder refreshes every number and
  sentence on the page.

## Links

Pages use pretty permalinks (`/guide/loci/`), so a relative link such as
`guide/loci` breaks on any page that is not at the site root. Link with the
`relative_url` filter instead: {% raw %}`[Loci]({{ '/guide/loci/' | relative_url }})`{% endraw %}.

Each page uses `just-the-docs` front matter:

- `nav_order`: position in the left sidebar.
- `parent`: nest inside a parent section.
- `has_children: true`: make the page a section root.
