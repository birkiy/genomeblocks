What it is

Same peaks, two ways to store them

Objects keep each peak together in its own box. Columns keep each field together: all chromosomes in one array, all starts in the next, all ends in the next. Nothing about a peak changes; only where its four numbers sit in memory.

Four peaks, objects vs columns

Measured on 1M peaks: 222 bytes per peak as objects (the Python object header, its attribute dict, and separate integer objects for start and end), 25 bytes as columns. Loading 1M peaks takes 2.0 s as objects and 302 ms as columns.

Why columns are faster for whole-set work: an operation such as "which of these peaks overlap that set" runs as a few calls over whole arrays, compiled code walking memory in order, instead of one Python step per peak. Summing every start: 3.6 ms as a Python loop over objects, 159 µs as one numpy call over the column.

pandas, polars, Arrow

Is that a DataFrame?

A DataFrame is already column data. pandas, polars, Arrow and the proposed Loci all hold arrays; what differs is what each adds around them, and how fast one row can be read.

Same arrays, different wrappers

Arrow is the common format: polars, DuckDB and R's arrow package read it without copying, and pandas can too. A columnar Loci built on plain numpy arrays can hand its arrays to any of them almost for free, and genomeblocks keeps its own genomics layer on top.

Your code

Code that uses Loci does not change

loci[i] and for peak in loci still hand you a Locus. It is a small view onto row i that reads and writes the columns.

What loci[2] returns

The view is a real Locus subclass, so isinstance checks, uid, distance_to, overlaps, sequence and printing all behave as today. Editing it edits the stored peak.

# unchanged, works on both storages
cre = Loci.make("atac.narrowPeak").slop(100).sort().merge()
for peak in cre[:5]:
    print(peak.uid, peak.length)
arch = Architecture.make(cre, "loops.bedpe", r=2500)

# new with columns: whole arrays, and free hand-over to other tools
cre.starts, cre.ends               # numpy arrays
cre.to_polars(); cre.to_arrow()    # no per-row copy

Objects

What objects give us

Fast plain loops

A Python loop over objects is the fastest per-peak code: 3.6 ms for 100k vs 65 ms through views. Anything written as "for peak in loci" is quickest on objects.

Nested structure

Gene → Transcript → Exon/CDS/UTR is a tree. Objects model it directly (g.transcripts[t].exons); columns need linked tables and an index to walk it.

Per-item fields and methods

Exon.exon_number, UTR.type, Transcript.tss_score, Gene.canonical; sequence(), distance_to(). Columns can hold extra fields, but each needs declaring.

Identity and editing

An object is a thing you can edit, put in a set or use as a dict key. Views edit too, but loci[0] is loci[0] becomes False: two views of one row are equal, not identical.

Mixed types in one container

Today a Loci can hold Genes, Transcripts and plain peaks at once (the annotation index does). Columns need one schema per container.

Easy to read and debug

No numpy knowledge needed; printing a peak shows a peak. This is a real advantage for users writing their own code.

What objects cost: 9× the memory, a Python step per peak for every bulk operation, and a full conversion each time data goes to pandas, pyranges or a faster engine. With views, the convenience stays where it is used (one peak at a time) and the cost goes away where it hurts (whole sets).

Genes

Genes: a tree, stored as linked tables

Gene models as columns

Parsing the GTF into tables takes 550 ms instead of 5.6 s, and the annotation index builds from them in 150 ms instead of 4.0 s. Gene and Transcript views would keep g.transcripts[t].exons working, the same way LocusView keeps loci[i] working.

Recommendation

Columns for storage, objects as views

1 · Columnar Loci with LocusView

Same public API; 14/14 functions already give identical output. Set operations, sort, merge, slop, make and the to_ conversions move to arrays.

2 · Rewrite the four per-peak hot loops

Genes.annotations, Atlas binning, count_pairs grouping and signal's array copy read the columns directly, so nothing gets slower.

3 · Genes as linked tables

Gene / Transcript views on top, so annotate and nearest_genes become array work end to end.

Watch for

Code that relies on loci[i] is loci[i] (identity), and users who subclass Locus to add their own fields; both need a note in the release.

Method

How this was measured

  • Prototype: benchmarks/prototypes/columnar.py (ColumnarLoci + LocusView, about 250 lines). Bench: bench_columnar.py. genomeblocks itself was not modified.
  • Same machine and synthetic hg38-shaped data as the benchmark report; medians of 3–5 runs after a warm-up; memory with tracemalloc.
  • Every pair of outputs was compared: same intervals, same tables, same signal cube, same motif matrix, same graph edges and vertex labels.
